Product 01

Workflow Canvas

A node canvas is powerful and intimidating in equal measure. Across these four features the question was the same: how does a complex tool stay intuitive, so people get to a result without first learning the system?

01Workflow Canvas

One chatbot, two audiences

Conversational UI2C2BInteraction model

The canvas needed a chatbot so people could drive generation in plain language. But a solo creator and a brand team want opposite things from it — so I designed two interaction models on one visual system.

The everyday creator2C · makes content alone
Speed
I just want the image. I don’t want to learn what a node is first.
Pain point
A full workflow canvas is too much to learn for one quick asset.
What they need
The shortest path from an idea to a result.
The brand team2B · ships campaigns at scale
Accuracy
If step three of a long workflow is wrong, I can’t afford to find out at the end.
Pain point
One-shot generation of a complex workflow is unpredictable and hard to correct.
What they need
To see the plan first, and to change any single step afterwards.
2CSpeed & simplicity

Break the workflow into single functions, and let the chat be the hook

Instead of exposing the whole canvas, the 2C chatbot splits the workflow into standalone node functions. The user picks the kind of asset they want, talks to the chatbot, and gets it in a single back-and-forth. Once they have seen what one node can do, the full canvas is one step away.

01

Pick an asset type

Image, video, audio — each one is a single node function.

02

Describe it in chat

One prompt, optional references.

03

Result in one exchange

No setup, no canvas to learn.

→

Continue on the canvas

The hook into the full, more capable workflow.

2C user flow
2BAccuracy & control

Plan first, then generate step by step

For professional teams the priority is that a complex workflow comes out right. So the 2B chatbot never generates in one shot: it first turns the request into a plan — a main task with a to-do list — and waits for confirmation. Only then does it build the workflow node by node, and every node stays open to inspection and adjustment.

01

State the goal

The user describes the whole deliverable.

02

Review the plan

Main task + to-do list, before anything runs.

03

Confirm

Nothing is spent until the plan is approved.

04

Step-by-step generation

Each node reports its own status.

05

Adjust any node

Change one step without redoing the rest.

Product 02

Pulse

Pulse is Vicino’s AI content-lifecycle platform. It learns a brand, then helps a marketing team plan, produce, approve and publish its social content in one place.

As the product designer, I worked directly in code: I built interactive prototypes with Claude Code and iterated on them quickly, so each design update could be tried, reviewed and revised as a working product rather than a static mock-up. Below is a selection of those iterations — what I changed, and why.

08Pulse

AI chat: three fixes from real usage

Usability issuesError recoveryIteration

After the chat shipped to the dev build I logged the problems I found using it, proposed the fixes, and prototyped each one. Three of them are below — the numbered pins mark where each problem showed up, and where its fix landed.

01Issue

Poor error recovery after an approved change fails

  1. Problem
  2. 1A technical error, shown twice — a red card, then an AI message repeating it.
  3. 2The change was already approved, yet the user is told to ask again from scratch.
  4. Fix
  5. 3One plain line — “Your post is unchanged.” — with an optional Why?
  6. 4The approved version stays on the card with a direct Retry. No new approval.
  7. 5The post being edited is marked “not updated”, so the failure shows where it happened.
02Issue

Attachments stacked up and pushed the conversation away

  1. Problem
  2. 1Each file took a full row of text. Five files hid most of the chat, and the names were hard to tell apart.
  3. Fix
  4. 2Compact thumbnail tiles in one row that scrolls sideways.
  5. 3Image previews and PDF / DOC labels first; file name and remove appear on hover.
03Issue

Chat history was hard to scan and impossible to manage

  1. Problem
  2. 1Titles were raw, truncated prompts, and every row had the same dot whatever its state.
  3. 2No search and no actions on a chat.
  4. Fix
  5. 3The main chat is pinned on top, apart from side chats.
  6. 4Short descriptive titles, grouped by Today / Yesterday / This week.
  7. 5Search, plus a ••• menu on hover: Rename, Pin, Archive, Delete.
